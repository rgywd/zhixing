# 知行 0.3.0

0.3.0 重新设计了 Work：手机不再充当开发监控面板，也不再复刻 Codex Desktop 或消费旧版 Happy / App Server
协议。手机创建会话后，Codex 在开发机自主执行，只在需要汇报、提问或交付长报告时通过三条“电话线”联系知行。

## 新版 Work Phone-line

- 在知行中选择开发机、白名单仓库、Codex 模型与思考深度后，直接像普通聊天一样发送第一条消息。
- Work 会话固定使用完全访问权限，不再暴露一套难以理解且容易失效的权限组合。
- 开发机 Runner 使用本机 Codex 登录态执行任务；普通桌面 Codex 会话不会被同步、修改或注入工具。
- Codex 仅获得 `report`、`ask`、`report_html` 三个专用 MCP 工具：即时汇报、结构化提问与安全 HTML 报告。
- `ask` 最多等待三分钟；手机未及时回复时任务会安全收口，稍后答复可通过 resume 继续。

## 原生移动交互

- Work 复用知行现有聊天页面骨架、输入框、Markdown 渲染和消息时间线，不再维护第二套聊天 UI。
- 模型与思考深度可在新建会话时选择；目录使用本地缓存乐观展示，弱网刷新失败不会锁死控件。
- 消息、提问答案、报告和命令均由 Work Core 持久化；断线重连后按事件序号继续，不依赖最近活跃窗口。
- HTML 报告在独立只读 WebView 中打开，禁用脚本、文件访问、外链跳转和网络加载。

## 可靠性与安全

- Runner 仅主动出站访问 Core；Core 不持有 Codex 账号、登录态或仓库源码。
- Runner、会话与短期 MCP token 相互隔离，支持撤销、命令租约、进程换代 fencing 和崩溃后的终态补交。
- STOP 在 Core 断线时仍会先终止本机 Codex，再持久化回执等待恢复后补交。
- 旧 Work、Happy、Relay、App Server 与 Agent 运行时已经删除；Room v33 升级会清理对应废弃表。

## 升级与配置

- 可从 0.2.2 直接覆盖升级到 0.3.0；普通聊天、助手、知识库和提供商设置不受影响。
- 旧版 Work 会话、Happy 凭据与 Codex catalog 会在升级时清理，不能在新版 Work 中继续使用。
- 首次使用请在设置的 Work 卡片中填写 Work Core HTTPS 地址和 Bearer Token，并保持开发机 Runner 在线。
- 当前 0.3.0 的 Work 消息输入为文本；图片和文件附件将在后续版本按 Phone-line 协议单独加入。
