# 长期用户画像 V2

状态：V2 已实现（Issue #93，2026-07-24 核对）

## 1. 目标

画像只描述跨任务、跨时间仍有用的用户特征、约束和痛点。一次任务里采用的工具、临时项目状态、助手的推测和单次表达都不能直接成为画像。

V2 参考 ChatGPT 的持续摘要、OpenClaw 的分层沉淀和 Letta 的有界上下文，采用以下链路：

```text
用户消息原文 -> 待验证观察 -> 合格观察 -> 每维一条长期摘要 -> 聊天上下文
```

数据库升级时直接清空旧版自动/手动 `PROFILE`。旧版画像质量不可控，不做内容迁移；普通 `CONTEXT` 记忆保留。

## 2. 数据层次

### 原文证据

每条证据保存 `conversationId`、`messageId`、用户文本片段和消息时间。规则层必须确认引用确实来自对应
用户消息，且引用是本轮提供给画像模型的原始文本部分子串。每条文本有长度上限，因此这里的“原话”不等于
附件原文或未截断的完整消息；客户端不会添加角色前缀或省略号。助手回复、系统消息和工具输出不进入证据源。

### 观察

`MemoryKind.OBSERVATION` 是内部记录，不进入聊天提示，也不直接展示为画像。模型只能提出创建、强化或冲突候选；本地规则负责真实性校验、证据累计、置信度、晋升和过期。

默认晋升条件：

- 至少 3 个独立对话；
- 首末证据至少跨 7 天；
- 本地确定性评分达到所选策略阈值；
- 内容属于四个长期维度，且不是敏感信息或一次性事项。

单次明确表达可以成为一条待观察信号，但不能绕过晋升门槛直接形成自动画像。

### 长期摘要

只有合格观察可以参与摘要。每个内置维度最多维护一条未锁定自动摘要，总量最多 4 条：

| ID | 展示名 | 内容边界 |
| --- | --- | --- |
| `identity_context` | 身份与背景 | 长期角色、领域、语言、环境和稳定约束 |
| `preferences_values` | 偏好与取向 | 稳定偏好、价值取向、反复出现的痛点和排斥项 |
| `capabilities_knowledge` | 能力与知识 | 长期技能、工具经验、知识领域和能力边界 |
| `behavior_collaboration` | 行为与协作方式 | 反复出现的沟通、决策、工作流、风险和交付偏好 |

提示词最多注入 8 条全局画像；V2 自动路径实际最多生成 4 条。内部观察永不注入。

周期任务、启动补跑和手动“立即维护”虽然由不同的 WorkManager 入口触发，但必须经过同一个进程级串行
门禁，不能同时读取旧快照并重复插入摘要。每轮维护开始时还会检查同维度的未锁定自动摘要；若历史并发
已经产生重复项，只保留处于生效状态且证据覆盖最强的一条，其余转为归档。手动画像、用户已编辑或锁定的
画像不参与这项自动收敛。

## 3. 置信度与生命周期

模型不再提交置信度。客户端按独立对话覆盖、时间跨度和独立日期数计算 0..1 分数，策略阈值仍为保守 0.90、均衡 0.80、积极 0.70。

- 新证据按 `messageId` 去重并累计，不能覆盖历史依据。
- 配置门槛变化时，已有观察会重新计算并在 `PENDING` / `ACTIVE` 间调整。
- 默认 180 天没有新证据的观察归档；失去合格观察支撑的自动画像随之归档。
- 明确冲突会归档旧观察并建立新的待验证观察。
- 用户编辑、确认或归档自动画像后，该记录锁定，后台任务不能覆盖或重新创建同维自动画像。
- 用户永久删除画像时，正文、引文和支撑关系会被清空并进入内部 `DELETED` 状态；该画像所引用的自动观察
  同时清空正文和证据，只保留维度与归并键的 SHA-256 指纹，用于阻止同一结论被下一轮原样重建。指纹不包含
  可读用户内容；仍引用这些观察的其他未锁定自动摘要同步归档，避免重复结论继续进入提示。删除一个结论不会
  关闭整个画像维度，其他独立观察仍可形成新摘要。
- 用户删除会话时，该会话的画像引文同步撤销；受影响且未经用户确认的自动观察和摘要归档，旧观察不再参与
  晋升。后续新对话可以形成新的独立观察。用户已经明确确认的画像正文继续作为显式记忆保留，但不再展示
  已删除会话的引文。

## 4. 模型输出契约

提取阶段返回带精确用户原话的观察候选：

```json
{
  "observations": [
    {
      "action": "reinforce",
      "targetObservationId": 12,
      "dimensionId": "behavior_collaboration",
      "content": "用户长期偏好先给结论，再补必要依据。",
      "durable": true,
      "sensitive": false,
      "evidence": [
        {
          "conversationId": "conversation-id",
          "messageId": "message-id",
          "quote": "先告诉我结论"
        }
      ]
    }
  ]
}
```

摘要阶段只能引用客户端提供的合格观察 ID，并且每个维度最多返回一条摘要。两阶段任一输出的未知维度、错误 ID、伪造引用、空内容或越权操作都会被逐项丢弃。

## 5. 调度与交互

- WorkManager 使用 `(conversation.update_at, conversation.id)` 增量游标，默认每 6 小时处理最多 20 个变化对话。
- 单会话和总批次字符预算都优先保留较新的用户消息；最终发送给模型时再恢复为时间正序，不能因为先消费旧消息
  而在游标推进后永久漏掉同一会话的最新表达。
- 周期、启动补跑和手动入口共享串行执行门禁；排队任务会在前一轮完成后重新读取游标和画像，不并发写入。
- 自动维护要求记忆、全局记忆和历史聊天参考同时开启，并复用快速模型。
- `memory_tool` 创建画像时必须提供四个内置维度之一；编辑、归档、恢复和删除只能访问全局 `PROFILE` 或
  当前记忆作用域的 `CONTEXT`，不能访问内部观察或其他助手的情境记忆。归档、恢复和永久删除执行前需要用户授权。
- 工具结果只返回记录 ID、类型、状态、正文和画像维度，不向模型回传历史引文、会话 ID、置信度或内部观察 ID。
- 自动维护与用户编辑、确认、归档、删除及会话证据撤销共享串行写入门禁；`DELETED` 是不可恢复、不可改写
  的终态，不能被删除前的旧实体覆盖。
- 设置项包含独立对话数、最短观察跨度、过期时间、策略、自动应用和批次上限。
- 自动画像展示本地评分、独立对话数，并可查看逐条用户原话及时间。
- 用户确认或编辑自动画像后，记录继续保留并展示原自动整理依据，同时明确标记为用户已确认或编辑；来源
  可追溯性不能因为记录转为手动锁定而消失。
- 关闭自动应用时，生成的长期摘要进入待确认区；内部观察仍按同一门槛累计。

## 6. 数据库与迁移

画像 V2 字段由数据库版本 36 引入；应用当前数据库版本为 39。`MemoryEntity` 在 v36 新增：

- `profile_evidence_json`：结构化原文证据；
- `supporting_observation_ids`：摘要所依据的观察 ID；
- `canonical_key`：观察归并键；
- `first_evidence_at`：首条证据时间。

已有的 `dimension_id`、`confidence`、`source`、`state`、`locked` 和 `last_evidence_at` 继续使用。迁移 `35 -> 36` 删除旧 `PROFILE`，保留 `CONTEXT`。

`DELETED` 是写入既有字符串状态列的内部删除标记，不新增数据库字段。删除标记不进入管理列表、Chat 或
“现在”面板；被删除记录的正文和证据必须已经清空。

## 7. 验收标准

1. 单个对话或同一对话的多条消息不能生成自动画像。
2. 助手文本和无法精确回查的引用不能成为证据。
3. 观察必须满足独立对话数、时间跨度和确定性评分后才可晋升。
4. 自动画像每个维度最多一条，且只由合格观察生成。
5. 证据持续累计，冲突、过期和用户归档会停止旧画像继续生效。
6. 升级清理旧画像但不删除普通情境记忆。
7. 用户能查看每条自动画像对应的用户原话。
8. 多个维护入口同时触发时仍每维最多一条自动摘要；旧版并发重复项会安全归档收敛。
9. 永久删除后的自动画像不会由原有支撑观察重新生成，且删除标记不保留用户正文或引文。
10. 删除会话会撤销该会话的画像证据，不再把已删除消息作为自动画像依据。
11. 画像摘要的存续按实际 `supportingObservationIds` 判断；任一已记录支撑失效时先归档旧摘要，而不是用
    同维无关观察继续维持。
12. 历史页 Undo 窗口结束前不执行会话删除或证据撤销；确认删除后，两者在同一个 Room 事务中提交。
