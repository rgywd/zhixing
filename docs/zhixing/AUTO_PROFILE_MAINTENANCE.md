# 自动画像维护：四维画像与增量整理

状态：首版已实现并完成 Debug 构建验证（2026-07-21）

## 1. 用户问题

现有“我的画像”只能由用户或当前聊天中的模型主动维护。即使已经开启全局记忆和历史聊天参考，过去对话里稳定、重复出现的个人偏好仍不会自然沉淀，画像因此长期为空或过时。

本功能使用已经配置的快速模型，按增量游标整理发生变化的普通聊天，并把候选信息维护到现有 `MemoryEntity` 体系中。它不新增模型工具、不阻塞聊天发送，也不把一次性事项误写成画像。

## 2. 四维画像

首版预置四个维度，但数据库只保存可扩展的 `dimension_id` 字符串：

| ID | 展示名 | 内容边界 |
| --- | --- | --- |
| `identity_context` | 身份与背景 | 长期角色、领域、常用语言、设备环境、长期背景 |
| `preferences_values` | 偏好与取向 | 产品审美、技术选择、兴趣、明确喜欢或排斥的方案 |
| `capabilities_knowledge` | 能力与知识 | 熟悉领域、技术栈、工具水平、已有经验和知识边界 |
| `behavior_collaboration` | 行为与协作方式 | 沟通风格、决策习惯、工作节奏、风险与交付偏好 |

未知维度必须保留并降级展示到“其他”，禁止因为客户端版本较旧而丢数据。

待办、截止日期、临时项目进展和一次性背景继续属于“记住的事”，不进入四维画像。

## 3. 调度与增量契约

- Android 使用唯一的 WorkManager 周期任务；默认间隔 6 小时，可选 1/3/6/12/24 小时。
- WorkManager 只保证执行窗口，不保证精确时刻。应用启动时检查是否漏跑，并补排一次任务。
- 首次启用先整理最近一批对话并把游标落到最新位置，避免有大量历史记录时从最旧对话开始、数天后才形成可用画像。
- 后续使用 `(conversation.update_at, conversation.id)` 作为稳定增量游标，只读取上次游标之后发生变化的对话。
- 单轮最多处理用户设置的对话数，默认 20。积压数据在后续轮次继续处理，不全量重扫。
- 只整理普通聊天当前选中分支的用户/助手文本；忽略系统提示、推理、工具日志、附件二进制和 Work 会话。
- 没有合格对话、快速模型不可用或功能关闭时安全退出，不影响正常聊天。

## 4. 模型输出契约

快速模型只生成结构化候选项，不能直接操作数据库：

```json
{
  "candidates": [
    {
      "action": "create",
      "targetMemoryId": null,
      "dimensionId": "behavior_collaboration",
      "content": "用户偏好先给结论，再补充必要技术细节。",
      "confidence": 0.91,
      "explicit": false,
      "evidenceConversationIds": ["conversation-id-1", "conversation-id-2"]
    }
  ]
}
```

规则层必须执行以下保护：

- 只接受四个首版维度；未知输出丢弃，未来版本再开放自定义维度生成。
- `confidence` 必须在 0..1；空内容、无证据、引用本批次外对话的候选项丢弃。
- 普通推断必须满足设置的最少证据次数；用户明确自述可使用单条证据。
- 手动创建、手动编辑或锁定的画像不能被自动任务覆盖。
- `edit/merge` 只能修改已有、未锁定的自动画像；不存在或不允许修改时丢弃，不静默转成新建。
- 关闭自动应用时，合格候选项进入 `PENDING`；开启时只有超过策略阈值的候选项进入 `ACTIVE`。
- 自动任务不创建 `CONTEXT`，也不永久删除记录。

策略阈值：保守 0.90，均衡 0.80，积极 0.70；默认均衡。

## 5. 数据契约

`MemoryEntity` 增加以下兼容字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `dimension_id` | `""` | 四维画像 ID；情境记忆为空 |
| `confidence` | `1.0` | 自动候选置信度 |
| `source` | `LEGACY` | `LEGACY` / `MANUAL` / `AUTO` |
| `evidence_conversation_ids` | `[]` | JSON 字符串，保存证据对话 ID |
| `locked` | `false` | 为真时禁止自动覆盖 |
| `last_evidence_at` | `0` | 最近证据时间 |

`MemoryState` 增加 `PENDING`。只有 `ACTIVE` 记录进入聊天提示；待确认画像单独展示。

运行配置和状态保存在 Settings DataStore：开关、间隔、策略、自动应用、最少证据、单轮上限、增量游标、最近运行结果与错误。

## 6. 交互

记忆页继续复用现有页面：

- “我的画像”使用四个维度 Tab 切换展示；每个维度每页最多 5 条，超过后在当前维度内分页。
- 待确认画像归入所属维度 Tab，并继续保留确认、编辑和归档操作；未知维度仍进入兼容区。
- “记住的事”和归档记忆沿用同一分页规则，每页最多 5 条，避免长列表撑满整个页面。
- 自动生成项显示来源、置信度和证据数量；手动编辑后自动锁定。
- 增加“画像自动维护”卡片：开关、最近运行摘要、“立即维护”和高级设置入口。
- 高级设置可调间隔、策略、自动应用、最少证据和单轮对话上限。
- `PENDING` 候选支持确认、编辑确认和归档。

## 7. 失败与降级

- 模型返回 Markdown 包裹 JSON 时允许提取 JSON；无法解析则记录失败，不推进游标。
- 网络/鉴权/限流失败交给 WorkManager 重试；用户主动运行时保留错误摘要。
- 单条候选非法只跳过该条；整个模型响应非法则本轮失败。
- 只有完成模型请求和候选落库后才推进游标，避免静默漏处理。
- 设置关闭时取消周期任务，已有画像和运行记录保留。

## 8. 验收标准

1. 用户可在记忆设置中启用自动维护并调整全部首版参数。
2. 周期任务与启动补跑使用同一唯一任务，不重复创建。
3. 增量查询不会反复处理未变化对话，批次截断后可从稳定游标继续。
4. 快速模型的非法、过度自信或证据不足输出不能污染画像。
5. 手动/锁定画像不被自动覆盖，待确认画像不进入聊天提示。
6. 画像按四维展示，未知维度可兼容显示。
7. 聚焦单测、Room schema/迁移编译、Debug 构建通过。

## 9. 延期

- 完整版本历史与逐字段冲突 UI。
- 向量召回、实体关系图谱和敏感信息分类器。
- 自定义维度创建及让模型自动写入自定义维度。
- 精确时刻调度和后台常驻服务。
