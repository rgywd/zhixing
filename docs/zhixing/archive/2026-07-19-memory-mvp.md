## 1. 产品目标

把当前无类型、全量注入的文本记忆升级为一个克制的个人上下文底座。用户只需要理解两个区域：

- **我的画像**：全局、稳定、原子化的用户事实和交互偏好。
- **记住的事**：全局或单助手范围内、可能变化的通用情境记录。

这两个区域共用同一套记忆存储和同一个模型工具。画像、日程、项目、关系或事项是数据语义，不各自增加模型工具或专项工作流。

## 2. 当前链路

当前 `MemoryEntity` 只有 `id`、`assistant_id` 和 `content`。启用记忆后，应用会取出当前范围内的全部记录，以 `id + content` 注入系统提示；模型通过单个 `memory_tool` 创建、整段编辑或删除记录。

结果是稳定画像与临时情境无法区分，旧记录没有生命周期，记录数量增长后会持续占用上下文。

## 3. v0.1 用户行为

### 3.1 我的画像

- 画像由多条可独立编辑的原子记录组成，不保存为一篇自动生成的长文。
- 画像只存在于全局范围；启用记忆的助手默认都能使用它。
- 适合保存称呼、语言、交互偏好、稳定工作背景、重要关系、长期目标和稳定约束。
- 用户明确说“记住”时可以直接保存；普通对话中推断出的画像必须先征得确认。

### 3.2 记住的事

- 承载用户明确要求保留的通用情境，不预设发票、日程、任务、联系人等业务类型。
- 继续尊重现有“全局记忆 / 单助手记忆”范围设置。
- v0.1 保留用户原话的完整语义，不承诺提醒、日历同步、任务执行或关系图谱。

### 3.3 修正与退役

- 模型在已有相关记录时必须编辑原记录，避免以新记录制造矛盾副本。
- 活跃记录可归档；归档记录不进入日常提示上下文。
- 用户明确要求永久删除时仍可硬删除。
- v0.1 不提供完整版本历史；`updated_at` 记录最近一次修正时间，版本链后续再做。

## 4. 数据契约

`MemoryEntity` 在保留现有字段的基础上增加：

| 字段 | 约束 | 说明 |
| --- | --- | --- |
| `kind` | `PROFILE` / `CONTEXT` | 画像或情境；旧记录迁移为 `CONTEXT` |
| `state` | `ACTIVE` / `ARCHIVED` | 生命周期；只有 `ACTIVE` 默认参与提示注入 |
| `created_at` | 非空毫秒时间戳 | 创建时间；旧记录迁移时使用 `0` 表示未知 |
| `updated_at` | 非空毫秒时间戳 | 最近修改时间；旧记录迁移时使用 `0` 表示未知 |

模型层的 `AssistantMemory` 使用枚举表达 `kind/state`，遇到未知数据库值时降级为 `CONTEXT/ACTIVE`，避免未来版本或损坏值导致整页不可用。

## 5. 检索与提示契约

- 启用记忆时始终读取全局活跃画像。
- 情境记忆读取当前助手选择的范围：全局或单助手。
- 画像与情境在系统提示中分区呈现，保留记录 ID，便于模型修正原记录。
- 归档记录不注入。
- v0.1 按最近更新时间限制情境记录数量，禁止继续全量注入；语义召回延期。
- 画像同样设置数量上限，防止画像被滥用为知识库。

## 6. 模型工具契约

模型侧继续只暴露一个 `memory_tool`，不按类型或业务场景增加工具。

支持的动作：

- `create`：创建画像或情境记录；`kind` 必填。
- `edit`：修改已有记录内容，不改变其类型和范围。
- `archive`：使记录退出日常提示上下文。
- `restore`：恢复已归档记录。
- `delete`：仅在用户明确要求永久删除时使用。

检索、分类、范围过滤、数量限制和生命周期判断由应用内部完成，不要求模型先调用读取工具。

## 7. 迁移与兼容

- 数据库从 v26 增量迁移到 v27，不重建数据库。
- 所有旧记忆保留原 ID、`assistant_id` 和 `content`，并补为 `CONTEXT + ACTIVE`。
- 旧备份仍由 Room 在恢复后走同一迁移链。
- 现有助手的启用记忆、使用全局记忆配置保持不变。

## 8. 明确不做

- 不做任务中心、提醒器、日历同步或联系人管理。
- 不做不同业务类型的专用工具。
- 不做实体关系图谱、向量数据库或自动知识库化。
- 不做全量版本历史、跨设备冲突合并或云端画像。
- 不让模型看到更多常驻工具。

## 9. 验收标准

1. 升级后旧记忆全部出现在“记住的事”，内容和范围不变。
2. 用户可以分别新增、编辑和删除画像或情境记录。
3. 全局画像与当前范围的情境记忆分区注入，归档记录不注入。
4. 模型工具数量不因画像或生命周期能力增长，仍只有一个 `memory_tool`。
5. 明确纠正已有记忆时，工具说明要求 `edit` 而不是创建重复记录。
6. 聚焦单测覆盖旧值降级、提示分区/上限和工具 schema；Room 生成并校验 v27 schema。
7. `:app:assembleDebug` 通过。

## 10. 延期升级信号

只有出现真实使用证据后再增加能力：

- 用户需要按时间主动提醒：评估通用事件/调度适配器。
- 情境记录超过最近记录上限且召回明显变差：评估语义检索。
- 用户频繁追溯修改：增加版本链和来源引用。
- 用户需要跨应用执行：在授权层之上增加外部适配器，不修改记忆核心工具数量。
