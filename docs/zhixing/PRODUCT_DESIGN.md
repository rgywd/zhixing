# 知行 Android 重构：产品与体验设计

状态：实施基线（2026-07-20 更新）

## 1. 产品决定

知行从当前成熟的 Android 基座直接起步，定位为 Android-first 的个人 AI 工作台。旧 `zhixing-assistant` 仅作为历史原型保留，不再承担新产品的架构约束。

- Story Engine 视觉语言作废，不做兼容或渐进迁移。
- 基座已有的聊天、助手、模型供应商、工具、工作区和本地持久化能力作为主链。
- 模型请求与会话运行默认在设备端完成，远端 Ktor 不再是聊天必经层。
- Desktop 暂不进入首期范围；自适应大屏布局仍需在 Android 平板和横屏可用。
- 不复制上游商标、图标或社区入口；依法保留版权、许可证与源码说明。

## 2. 首期用户闭环

用户首次打开应用后，可以：

1. 添加一个 OpenAI-compatible、Claude 或 Gemini 服务商并选择模型。
2. 从会话首页新建聊天，输入文本或添加附件。
3. 观察流式生成，停止、重试、编辑消息并切换消息分支。
4. 在会话抽屉中搜索、置顶、分组、切换或删除会话。
5. 创建不同助手，为每个助手配置模型、系统提示、工具、记忆和工作区。
6. 数据默认保存在本机；只有用户主动配置的模型、搜索、MCP 或同步服务会收到必要数据。

## 2.1 Work：Codex 手机电话线

Work 不是第二套 Codex 客户端，也不是任务监控大盘。它解决一个更窄的问题：Codex 在开发机自主工作时，
用户可以离开电脑，用手机继续收消息、回答关键问题和查看最终报告。

首期闭环只有手机主动创建的 Work 会话：

1. 用户选择已登记的仓库、Codex 模型和思考深度并发送第一条普通消息。
2. 开发机 Runner 使用固定的完全访问策略启动一次隔离的 Codex CLI 会话。
3. Codex 只通过 `report`、`ask`、`report_html` 三个 MCP 工具联系手机。
4. 手机把汇报显示成聊天消息，把问题显示成原生选择卡，把长报告显示成可打开的报告卡。
5. 用户补充消息或回答问题后，Runner 使用同一个 Codex session resume，不创建“调研进度”的替代会话。

进入会话后沿用普通聊天的页面骨架、消息排版和输入框行为；不先弹“任务表单”，不展示工具日志、终端流、
隐藏推理或桌面历史。权限固定为完全访问，不在手机提供其他权限档位。

## 3. 信息架构

一级入口保持克制：

- 会话：默认首页，包含当前对话、会话抽屉和新建入口。
- 助手：管理角色、默认模型、提示词、记忆与工具能力。
- 工作区：管理文件与任务执行上下文。
- 设置：模型服务、搜索、语音、MCP、外观、数据和关于。

Work 作为会话侧的轻入口存在，包含会话列表、新建和详情；电脑、仓库与连接配置收在原设置页的 Work 卡片中，
不另造一套设置首页。普通 Chat 与 Work 数据、列表和创建动作互不混用。

“笔记”不再作为独立底部主导航强行存在。首期将旧笔记能力映射为工作区文件、记忆或工具输出；只有验证出高频独立浏览需求后，才新增一级入口。

## 4. 视觉语言

采用 Material 3 Expressive 与 Android 原生自适应规范，建立知行自己的语义令牌，不保留 Story Engine 的纸张、墨色、编辑部或叙事化装饰。

- 品牌：名称使用“知行 / Zhixing”，图标独立设计，不复用上游标识。
- 色彩：默认支持系统动态色；固定主题使用中性表面加单一强调色，明暗模式均以可读性为先。
- 排版：正文、代码、辅助文字各有稳定层级；长内容在平板限制可读宽度。
- 间距：4/8dp 节奏；关键触控区不小于 48dp。
- 图标：统一使用现有矢量图标体系，不使用 emoji 充当结构图标。
- 动效：150–300ms 的原生过渡；支持减少动态效果，不用位移造成布局抖动。
- 布局：手机使用模态会话抽屉，大屏横向使用永久抽屉；系统栏、安全区和输入法由 Scaffold/insets 统一处理。

## 5. 关键状态

每个主要页面必须显式覆盖：加载、空状态、可恢复错误、离线/上游不可用、内容状态和破坏性操作确认。聊天页另外覆盖生成中、停止中、工具等待授权、部分结果保留和分支切换。

## 6. 首期不做

- 不迁移旧应用的数据库、token 或未提交功能。
- 不维持旧 Ktor REST/SSE 契约兼容。
- 不同时维护 Compose Multiplatform 和 Android 两套 UI。
- 不在首期重写基座已成熟的聊天渲染、Provider 或工具流水线。
- 不接入知行自有云端账号、多人协作或跨端同步。
- 不同步或接管 Codex Desktop/CLI 的既有项目与历史会话。
- 不接入 Codex App Server，不兼容 Happy 协议，不恢复 Relay/Agent 消息翻译层。
- 不把终端、工具调用、审批流或思考过程镜像到手机。
- 不允许普通桌面 Codex 会话调用 Work 的三条电话线。

## 7. 验收标准

- 新安装可独立完成“配置模型 → 新建会话 → 流式回复 → 重开历史会话”。
- 手机、小平板和横屏大屏无内容被系统栏或输入器遮挡。
- 明暗模式文字和交互状态可辨；所有图标按钮有语义标签和至少 48dp 点击区域。
- 关闭或缺失任何可选远端服务时，本地会话浏览仍然可用。
- 应用不依赖上游 Firebase 项目、更新源或品牌服务即可构建和启动。
- Work 新建会话可选择仓库、模型和思考深度；网络恢复后可继续同一个 Codex session。
- `report`、`ask`、`report_html` 均可在 Android 原生界面完成闭环，Runner 退出也会产生明确状态。
