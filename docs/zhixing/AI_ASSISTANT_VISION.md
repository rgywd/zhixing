# 知行 AI 助手产品愿景

状态：长期产品基线（2026-07-21）

## 1. 产品定义

知行不是把模型、设备和工具堆进同一个 App 的功能集合，而是一个 Android-first、本地优先的个人 AI
操作系统：持续理解用户，接收现实世界事件，选择合适资源执行任务，只在值得打断用户的关键节点主动出现。

产品成功不以“接入了多少 Provider”衡量，而以闭环衡量：

```text
感知 -> 理解与记忆 -> 形成任务 -> 获得授权 -> 执行 -> 验证 -> 汇报或继续跟进
```

All in One 的含义是共享同一份用户上下文、任务状态和权限边界，而不是为每个能力增加一个首页入口。

## 2. 当前能力与资源

| 资源 | 当前定位 | 边界 |
| --- | --- | --- |
| 普通聊天 | 已能覆盖常见手机 AI 应用的多模型、流式、多模态和工具交互 | 继续复用成熟聊天链路，不为新领域重写输入框和消息渲染 |
| 百炼新加坡节点 | 通用模型与国际链路资源 | 由能力、网络、成本和隐私策略路由，不直接成为信息架构 |
| 火山引擎 Agent Plan | 文本、视觉、语音和向量化能力 | URL 与协议由客户端适配器维护，用户只提供必要凭据 |
| Codex Work | 开发机自主执行与手机关键沟通 | 只管理手机创建的会话，采用 Phone-line 契约，不同步桌面历史 |
| 用户画像与记忆 | 长期偏好、背景和情境底座 | 用户可见、可改、可归档、可删除；禁止演变成不可解释的黑盒档案 |
| 手表与健康数据 | 待验证的身体感知入口 | 优先评估 Android Health Connect 等标准入口；私有蓝牙协议作为独立研究，不阻塞健康能力 |
| Workspace 与知识空间 | 文件、项目资料、引用和本地工具上下文 | 用户原文是事实来源，索引和派生内容可重建 |

## 3. 五个用户概念

产品层只向用户暴露五个稳定概念，具体 Provider、协议和设备藏在其后：

1. **对话**：用户此刻想说、想问或想交给 AI 的事情。
2. **今天**：当前值得注意的日程、异常、等待回答和后台进展。
3. **任务**：AI 正在替用户做什么，卡在哪里，下一步是什么。
4. **记忆**：AI 长期知道什么，以及用户如何纠正、归档或删除它。
5. **连接**：AI 被允许感知和控制哪些服务、设备与数据源。

这五个概念是信息架构边界，不要求立即增加五个一级导航。新能力应优先融入现有页面与交互，而不是另造一套 UI。

## 4. 六层能力模型

### 4.1 感知层：统一收件箱

所有输入先归一为带来源、时间、敏感级别和处理状态的事件：

- 用户消息、系统分享、图片、文件、录音、截图和剪贴板内容；
- 邮件、日历、待办和重要系统通知；
- Codex 汇报、提问、报告与完成状态；
- 电脑、浏览器、服务器、智能家居和未来可穿戴设备事件；
- 心率、睡眠、活动等经用户授权的健康数据。

事件进入同一时间线和任务系统，不为每个数据源复制一套收件箱。

### 4.2 记忆与情境层

- **画像**保存长期稳定的身份、偏好、能力和协作方式。
- **记住的事**保存用户明确要求保留或仍有价值的情境。
- **当前情境**由时间、位置、设备、日程、正在查看的项目和活跃任务临时组成，不自动沉淀为长期记忆。
- 回答和行动应能说明使用了哪些记忆；敏感或低置信推断不得静默固化。

### 4.3 任务与目标层

一次聊天不是长期工作的唯一容器：

```text
目标（数周或数月）
  -> 任务（有开始、等待、完成状态）
      -> 会话或执行轮次（本次具体交互）
```

会话可归档而目标和任务继续存在。统一任务状态至少覆盖：待开始、进行中、等待用户、等待外部条件、完成、失败、取消；
每个任务保留来源、负责人、下一步、截止时间、关联会话和可验证结果。

### 4.4 行动层

所有可产生外部影响的能力采用统一行动闭环：

```text
建议 -> 风险判断 -> 必要时确认 -> 执行 -> 验证结果 -> 汇报 -> 可撤销或补救
```

优先补齐日历、提醒、系统分享和文件四个基础连接器，再扩展邮件、浏览器、电脑、服务器、智能家居和个人云盘。
Codex 是开发领域的执行器，不应成为所有生活任务的通用中间层。

### 4.5 主动协作层

“今天”聚合近期日程、正在运行的任务、等待回答、重要变化、到期承诺和健康异常。主动触达分四级：

| 等级 | 行为 |
| --- | --- |
| 静默记录 | 进入时间线，不通知 |
| 普通提醒 | 在合适时间提醒，可稍后处理 |
| 请求决策 | 明确说明为什么需要用户选择，并提供快捷回答 |
| 紧急中断 | 仅用于用户设定的高优先级、安全或健康风险 |

所有主动策略都必须可关闭、可调频并解释触发原因。`report`、`ask`、`report_html` 的思想可扩展为长任务的通用协作语义，
但具体协议不强迫所有执行器复用 Codex Phone-line。

### 4.6 信任与控制层

- 每个连接器独立授权，临时权限与长期权限分离。
- 高风险操作必须确认，后台任务可以一键停止。
- 对外写入保留审计记录、验证结果和补救路径。
- 记忆可查看、修改、归档、删除，并能追溯来源。
- API Key、健康数据和私人内容默认本地加密；发送给云模型的上下文遵守最小必要原则。
- 单个 Provider、连接器或网络失败只降级对应能力，不锁死本地聊天、历史和设置。

## 5. 资源路由原则

用户表达意图，知行根据能力匹配、隐私级别、数据驻留、时延、成本、网络状态和用户偏好选择资源。用户可以覆盖选择，
但不需要先理解“这件事该交给百炼还是火山”。

路由至少区分：

- 普通问答与内容生成；
- 视觉、语音、向量化等专用能力；
- 本地记忆、知识空间和手机系统工具；
- Codex 等长时间、高权限执行器；
- 离线或弱网下的缓存、排队与降级路径。

同一个任务只能有一份权威状态。模型路由、失败重试或跨设备继续不得复制出多份互相冲突的任务记录。

## 6. 近期优先级

### P0：先形成个人闭环

1. 统一事件模型和关键通知中心。
2. 打通“任务 -> 提问 -> 用户回答 -> 继续执行 -> 完成报告”。
3. 建立行动审计、确认、停止和失败恢复的公共契约。
4. 让普通聊天、Work、画像和记忆共享一致的消息、任务和提醒语义，避免重复实现 UI。

### P1：补齐基础连接

1. Android 系统分享入口。
2. 日历与通用提醒。
3. 文件、图片、录音的统一采集和引用。
4. “今天”聚合视图与可解释的提醒分级。
5. Health Connect 可用性验证和健康数据最小只读闭环。

### P2：扩展行动半径

- 邮件与个人云盘；
- 浏览器与电脑协作；
- 服务器、NAS 与智能家居；
- 目标管理、周期复盘和跨来源自动化。

每一项新连接必须先完成一条可验证的真实任务闭环，再决定是否进入稳定入口。

## 7. 验收信号

- 用户从任意常见入口把信息交给知行后，可以找到它、继续处理并知道最终结果。
- 长任务离开前台或跨越数小时后仍能恢复，不需要新开会话重新询问进度。
- 只有值得用户处理的节点发通知，普通执行细节留在时间线。
- 用户能回答“AI 为什么知道这件事、为什么现在提醒、刚才替我做了什么”。
- 关闭任意云端 Provider、设备或连接器后，其他本地能力仍可使用。
- 新能力优先复用普通聊天、统一任务和权限组件，不产生平行的消息渲染、输入框或设置体系。

## 8. 明确非目标

- 不以接入数量、首页入口数量或模型数量作为产品完成度。
- 不默认常驻监听所有手机内容，不绕过 Android 权限和用户授权。
- 不让模型在缺少确认、审计或补救方案时执行高风险外部操作。
- 不把画像等同于任务、日历或健康档案，也不把一次性情境永久化。
- 不为了统一而强迫所有能力经过同一个云服务或私有协议。
- 不在真实任务闭环尚未成立时先建设复杂多智能体编排平台。
