# 知行 AI 助手产品愿景

状态：长期产品基线（2026-07-23）

## 产品定义

知行是 Android-first、本地优先的个人 AI 助手。它持续理解用户、接收现实世界事件、协助执行任务，
只在值得打断用户的节点主动出现。

产品以闭环而非接入数量衡量：

```text
感知 -> 理解与记忆 -> 形成任务 -> 获得授权 -> 执行 -> 验证 -> 汇报或继续
```

All in One 指共享用户上下文、任务状态和权限边界，不是给每个 Provider、设备或工具增加独立入口。

## 用户只需要理解五个概念

| 概念 | 用户问题 | 产品边界 |
| --- | --- | --- |
| 对话 | 我现在想问什么、交代什么？ | 复用成熟聊天链路，不为新能力重写输入框和消息渲染 |
| 今天 | 现在有什么值得注意？ | 聚合日程、异常、等待回答和后台进展，不等于第二个任务列表 |
| 任务 | AI 正在做什么、卡在哪里？ | 有来源、状态、下一步和可验证结果，可跨会话继续 |
| 记忆 | AI 长期知道我什么？ | 用户可见、可改、可归档、可删除，并能追溯来源 |
| 连接 | AI 能访问哪些服务和设备？ | 每项能力独立授权、独立降级，不把协议暴露为信息架构 |

这五项是产品边界，不要求成为五个一级导航。

## 设计原则

1. **本地事实优先。** 会话、任务、记忆和用户文件以本地数据为主；云能力失败不能锁死浏览和设置。
2. **复用普通聊天。** 图片、文件、Markdown、推理、模型与工具交互只维护一套用户体验。
3. **任务独立于会话。** 会话可以归档，长期任务仍保留状态、下一步和结果。
4. **行动必须闭环。** 外部写入遵循“风险判断 -> 必要时确认 -> 执行 -> 验证 -> 汇报/补救”。
5. **主动但克制。** 普通过程留在时间线；等待用户、完成、失败和高优先级异常才通知。
6. **记忆可解释。** 一次性情境不自动变成长久画像，敏感或低置信推断不得静默固化。
7. **实现藏在连接之后。** 模型、搜索、语音、设备和执行器各有独立契约，不在愿景中维护供应商清单。

## 能力演进

| 优先级 | 目标 |
| --- | --- |
| P0 | 打通“任务 -> 提问 -> 回答 -> 继续 -> 完成报告”，统一确认、停止、失败恢复和通知语义 |
| P1 | 补齐系统分享、日历提醒、文件/图片/录音采集，以及“今天”聚合视图 |
| P2 | 扩展邮件、云盘、浏览器、电脑、服务器、智能家居、健康数据和周期复盘 |

每项新连接必须先完成一条真实、可验证的任务闭环，再决定是否进入稳定入口。当前能力和实施状态只在
[`README.md`](./README.md) 及对应领域契约维护。

## 验收信号

- 信息从常见入口进入后可查找、可继续，并能看到最终结果。
- 长任务离开前台或跨越数小时后仍可恢复，不需要重新询问进度。
- 用户能回答“AI 为什么知道、为什么提醒、刚才做了什么”。
- 关闭任意云端 Provider、设备或连接后，其余本地能力仍可使用。
- 新能力复用聊天、任务、权限和通知组件，不产生平行交互体系。

## 非目标

- 不以模型、Provider、设备或首页入口数量衡量完成度。
- 不默认监听全部手机内容，不绕过 Android 权限和用户授权。
- 不让模型在缺少确认、审计或补救方案时执行高风险操作。
- 不把画像等同于任务、日历或健康档案。
- 不在真实闭环成立前建设复杂的多智能体编排平台。
