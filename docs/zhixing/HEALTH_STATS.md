# 健康统计与结构化身体数据契约

状态：v1 实施契约（2026-08-17）

## 目标与边界

知行在现有统计页中提供第三个“健康”子 Tab，用于集中查看身体组成、生命体征、活动与睡眠数据。该页面是
只读视图，不承担设备连接、同步、手工录入或医学诊断；设备操作继续位于“设置 → 设备”。

当前数据分成两类：

- 结构化健康记录以 Room `health_metric_records` 为事实来源，保留测量值、规范单位、测量/记录时间、来源类型，
  以及可选的来源会话和消息 ID；
- Lenovo Watch Pro 继续以设备探针的最近同步快照为事实来源。健康页只读合并该快照，不把它复制成 Room 历史。

当前不接入 Health Connect、第三方体脂秤或云端健康平台，也不建立诊断、治疗建议或风险评分能力。后续数据源
必须转换成相同的规范指标类型和单位后再进入展示层。

## 指标与单位

v1 支持以下指标组：

- 身体档案：身高 `cm`、体重 `kg`、体脂率 `%`、BMI `kg/m²`；
- 身体组成：肌肉量 `kg`、骨骼肌率 `%`、体水分率 `%`、内脏脂肪等级、骨量 `kg`、腰围 `cm`、
  基础代谢 `kcal/day`；
- 生命体征：心率 `bpm`、血氧 `%`、收缩压/舒张压 `mmHg`、体温 `°C`、免疫等级；
- 活动与睡眠：步数、活动卡路里、运动分钟/次数、总睡眠/深睡/浅睡分钟、清醒次数。

持久值统一使用十进制定点字符串，最多三位小数，禁止 JSON 浮点数；每个指标在工具和仓储边界执行宽松的
物理范围校验。范围校验只用于拒绝明显损坏的数据，不代表医学正常范围。

当没有显式 BMI 记录、但同时存在身高和体重时，UI 使用 `kg / m²` 确定性计算一位小数的 BMI。该派生值
标记为“根据身高体重计算”，不写回 Room，也不作为用户明确提供的事实。

## AI 写入与读取

所有普通聊天提供本地工具 `health_metrics`，以 `action` 区分：

| action | 行为 | 约束 |
| --- | --- | --- |
| `save` | 保存一条或多条结构化测量 | 仅接受当前聊天 USER 文本中逐字存在的来源片段；每个提交数值都必须在该片段中明确出现 |
| `query` | 查询最近结构化记录 | 仅在“允许 AI 使用身体数据”开启时可读 |
| `delete` | 按稳定记录 ID 删除 | 必须绑定当前聊天中逐字存在的用户删除请求 |

AI 不得从照片、外观、年龄、性别、人口统计、模糊描述或所谓经验值推断身高、体重、体脂率及其他指标；
也不得把“大概偏高”“看起来很瘦”等描述转换成数值。来源片段必须绑定真实会话 ID 与用户消息 ID，
`health_metric_records` 不重复保存该原文。缺少明确测量时间时只记录写入时间，不猜测历史日期。

同一会话消息、指标、数值和测量时间生成稳定记录 ID，重复工具调用保持幂等。工具 schema 和执行层都拒绝
未知字段、未知指标、数值型 JSON、超限小数、未来测量时间和明显越界值。工具调用进入聊天持久化前会剥离
未支持的顶层与嵌套字段。

“允许 AI 使用身体数据”只控制模型读取已有结构化记录和当前生活上下文。用户在聊天中明确陈述数值并要求保存
时仍可触发写入；这不授权模型读取其他健康记录，也不放宽明确原文与数值校验。

## 统计页投影

`Screen.Stats` 固定包含“对话”“收支”“健康”三个子 Tab，不新增健康路由。健康页按以下顺序生成投影：

1. 读取 Room 中每个指标最新的结构化记录，并保留最近记录列表；
2. 合并 Lenovo Watch Pro 最近同步快照；同一指标以较新的有效时间为准；
3. 在没有显式 BMI 时按最新身高、体重派生 BMI；
4. 展示每个指标的来源与时间，缺失值显示为空状态，不补全、不估算。

页面顶部只展示数据源概况和“管理设备”入口。连接、解绑、同步和权限操作不得复制进统计页。

## 数据库与升级

数据库 v48→v49 只新增 `health_metric_records` 表及指标/有效时间、记录时间、来源消息索引；不修改、删除或
重建既有聊天、记忆、Agenda、月度收支、Work 会话、设备快照或用户文件。迁移必须由 Room schema 导出和
设备迁移测试共同验证。
