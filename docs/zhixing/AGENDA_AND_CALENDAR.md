# 事项、长期计划与弱日历契约

状态：v3 已实现（2026-08-01）

## 1. 产品边界

事项是主角，日历只提供时间背景。简单待办与长期计划共同出现在普通聊天右侧的“我的事项”区域；
右侧栏只投影当前行动，完整计划和阶段时间线进入独立事项页，不复制普通聊天的输入、消息或工具交互。

- 简单待办、长期计划和阶段节点均由知行本地 Room 数据库持有，是唯一权威数据。
- 系统日历通过 Android `CalendarContract` 只读投影，知行不复制日历事件。
- 未授权日历时，待办与长期计划的创建、编辑、完成和提醒仍可正常使用。
- 点击日历事件交给系统日历处理；现有日历查询与创建工具继续沿用原有权限边界。

## 2. 用户交互

右侧栏分区展示以下事项摘要：

1. 已逾期或当天到期的简单待办；
2. 没有截止时间的收件箱待办；
3. 已到触发、计划、截止或提醒时间，或尚未设置阶段时间的当前计划阶段。

未来待办、即将开始的计划节点、等待下一阶段的计划，以及已完成内容进入完整事项页。完整事项页将未来待办、
计划节点与系统日历按时间合并展示；全天日历事件按其全天日期显示，不伪装成某个时刻。用户可以在
右侧栏快速新增、编辑和完成简单待办，在完整事项页恢复或删除待办，并为未来时间开启本地通知。
两个手动待办入口在未显式选择截止时间时，都会解析标题中的“今天 / 明天 / 后天 + 时刻”快捷输入。

完整事项页的新增入口可选择简单待办或长期计划。手动长期计划包含一个发生时间和有序阶段；阶段时间
既可使用绝对时间，也可使用相对发生时间的分钟偏移，例如 `-21600` 表示提前 15 天。计划详情允许编辑
父计划与已有阶段；编辑会原子保存整组数据，但不会增删或重排已有阶段。系统日历默认只读投影未来 7 天，
日历授权入口只在尚未授权时出现。

“进入今天”只表示收件箱归类，不表示紧急。无截止时间的待办不得单独触发“现在去处理”的状态建议；状态理解
需要区分无截止、逾期、两小时内临期、今天稍后和未来事项，并引用具体事项作为依据。

简单待办可以按天、周或月重复，并设置 1～999 的间隔。重复任务当前行代表系列的当前实例；完成当前实例时，
它不会进入“已完成”分组，而是按设备时区推进到严格晚于完成时刻的下一次，继续保持待处理。跨夏令时按本地钟点
推进，截止时间与提醒时间之间的偏移保持不变。

## 3. 数据契约

`agenda_tasks` 是简单待办权威表，核心字段如下：

| 字段 | 含义 |
| --- | --- |
| `id` | 本地稳定 UUID |
| `title` / `note` | 标题与备注 |
| `status` | `PENDING`、`COMPLETED` 或 `CANCELLED` |
| `due_at` | 可选截止时间，毫秒时间戳 |
| `reminder_at` | 可选提醒时间，必须晚于创建或修改时刻 |
| `source` | `MANUAL` 或 `CHAT` |
| `conversation_id` | 可选来源会话，为后续追溯保留 |
| `created_at` / `updated_at` / `completed_at` | 生命周期时间 |
| `recurrence_frequency` / `recurrence_interval` | 可选 `DAILY`、`WEEKLY`、`MONTHLY` 与 1～999 的重复间隔 |

`agenda_plans` 与 `agenda_plan_stages` 是长期计划的权威表：

| 实体 | 核心内容 |
| --- | --- |
| 计划 | 稳定 ID、标题、说明、地点、状态、发生时间、来源、来源引用与生命周期时间 |
| 阶段 | 所属计划、顺序、状态、计划/触发/截止/提醒时间，以及相对计划发生时间的可选偏移 |

阶段随父计划级联删除；完成阶段不会自动完成父计划，父计划状态需要独立落定。数据库 v37→v38 只新增
`agenda_tasks`，v38→v39 只新增长期计划、阶段表与索引，v41→v42 只给待办增加可空重复频率与默认间隔；
这些迁移都不修改或清理既有用户数据，旧待办升级后仍是不重复任务。

## 4. AI 工具契约

普通聊天始终可见以下本地工具：

| 工具 | 行为 | 是否确认 |
| --- | --- | --- |
| `task_list` | 读取当前可见待办 | 否 |
| `task_create` | 创建待办或提醒 | 是 |
| `task_update` | 修改标题、备注、截止或提醒时间 | 是 |
| `task_complete` | 完成或恢复待办 | 是 |
| `task_delete` | 永久删除待办 | 是 |

时间参数接受 ISO-8601 或设备时区下的 `yyyy-MM-dd HH:mm`。写操作必须走普通聊天已有的工具确认机制；
工具和右侧栏共享同一个 Repository，禁止产生第二份任务状态。

`task_create` 与 `task_update` 通过可选 `recurrence_frequency` 和 `recurrence_interval` 暴露同一重复契约。
频率使用 `DAILY`、`WEEKLY`、`MONTHLY`；间隔默认 1。周期任务必须至少有 `due_at` 或
`reminder_at`。`task_update` 省略重复字段时保持原值，传空 `recurrence_frequency` 时清除重复。

`calendar_create` 使用相同的两个可选字段。一次性事件继续写 `DTEND`；重复事件向 Android Calendar Provider
写标准 `RRULE` 与 `DURATION`，由设备日历负责展开实例和编辑单次例外。第一版不暴露结束次数或结束日期，
创建的是持续系列。

长期计划工具遵守同一审批边界：

| 工具 | 行为 | 是否确认 |
| --- | --- | --- |
| `plan_list` / `plan_get` | 读取计划摘要或完整阶段时间线 | 否 |
| `plan_create` | 一次创建父计划及有序阶段 | 是 |
| `plan_update` | 修改父计划；相对阶段时间随发生时间重算 | 是 |
| `plan_stage_update` | 修改单个阶段及其时间 | 是 |
| `plan_stage_complete` | 完成或恢复单个阶段 | 是 |
| `plan_set_status` | 独立设置父计划状态 | 是 |

## 5. 提醒与降级

- 提醒由 WorkManager 使用唯一任务名调度；修改、完成或删除待办时同步替换或取消。
- 长期计划按阶段调度提醒；应用冷启动、设备重启、系统日期时间或时区变化后会从 Room 重建仍有效的提醒。
- WorkManager 提醒是系统调度的尽力送达，不承诺闹钟级精确时间，可能受系统节电策略延迟。
- Android 13 及以上需要通知权限；拒绝通知权限不会阻塞事项保存。有未来提醒且通知不可用时，界面会提示
  当前提醒无法弹出通知。
- 点击简单待办提醒会进入对应待办的编辑页；长期计划阶段提醒会进入对应计划详情。
- 手动编辑待办时，独立于截止时间的既有提醒会被保留；只有与截止时间绑定的提醒才随截止时间移动。
- 过期提醒不进入调度，恢复已完成待办时会清除已经过期的提醒时间。
- 完成周期待办当前实例后，会跳过已经错过的周期并只调度下一个未来提醒；重启和时区变化后仍从 Room 重建。
- 计划与简单待办的提醒重建彼此隔离；一类数据失败不会跳过另一类。
- 日历权限竞态或 provider 读取失败只清空当前日历投影，不影响本地事项。

## 6. 验收基线

- 冷启动后待办仍存在，数据库升级不破坏既有数据。
- 手动新增的待办立即出现在右侧栏，聊天工具创建的待办进入同一列表。
- 完成、恢复、删除会同步更新列表和提醒调度。
- 不授权日历时待办完整可用；授权后能看到近期系统事件并跳转到系统日历。
- 无截止时间的待办进入“收件箱”，不会计入“需要处理”或“今天”的紧急数量。
- “即将到来”按同一时间线合并未来待办、计划节点和未来 7 天系统日历，重复日历实例可以分别显示。
- 所有 AI 写操作都会要求用户确认，读取待办不会弹确认。
- 长期计划可以用绝对时间或相对发生时间表达跨周、跨月阶段；当前阶段会进入右侧行动投影。
- 用户可以手动创建长期计划，并在详情页原子编辑父计划与全部已有阶段。
- 完成阶段不会误完成父计划；计划、阶段与提醒在 v38→v39 迁移及冷启动后仍可读回。
- 每日、每周和每月任务能在完成当前实例后推进并继续提醒；一次性任务的完成与恢复行为保持不变。
- 重复日历事件以 RRULE 系列写入设备日历，设备日历可打开该系列并编辑单次实例。
