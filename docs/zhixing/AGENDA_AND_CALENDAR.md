# 事项、长期计划与弱日历契约

状态：v2 已实现（2026-07-24）

## 1. 产品边界

事项是主角，日历只提供时间背景。简单待办与长期计划共同出现在普通聊天右侧的“我的事项”区域；
右侧栏只投影当前行动，完整计划和阶段时间线进入独立事项页，不复制普通聊天的输入、消息或工具交互。

- 简单待办、长期计划和阶段节点均由知行本地 Room 数据库持有，是唯一权威数据。
- 系统日历通过 Android `CalendarContract` 只读投影，知行不复制日历事件。
- 未授权日历时，待办与长期计划的创建、编辑、完成和提醒仍可正常使用。
- 点击日历事件交给系统日历处理；现有日历查询与创建工具继续沿用原有权限边界。

## 2. 用户交互

右侧栏把以下内容合并为紧凑的当前行动：

1. 已逾期或当天到期的简单待办；
2. 没有截止时间的收件箱待办；
3. 已到触发、计划、截止或提醒时间，或尚未设置阶段时间的当前计划阶段。

未来待办、即将开始或等待下一阶段的计划，以及已完成内容进入完整事项页。用户可以在右侧栏快速新增、
编辑、完成或恢复、删除简单待办，并为未来时间开启本地通知。长期计划包含一个发生时间和有序阶段；
阶段时间既可使用绝对时间，也可使用相对发生时间的分钟偏移，例如 `-21600` 表示提前 15 天。
系统日历默认投影未来 7 天，日历授权入口只在尚未授权时出现。

“进入今天”只表示收件箱归类，不表示紧急。无截止时间的待办不得单独触发“现在去处理”的状态建议；状态理解
需要区分无截止、逾期、两小时内临期、今天稍后和未来事项，并引用具体事项作为依据。

## 3. 数据契约

`agenda_tasks` 是简单待办权威表，核心字段如下：

| 字段 | 含义 |
| --- | --- |
| `id` | 本地稳定 UUID |
| `title` / `note` | 标题与备注 |
| `status` | `PENDING`、`COMPLETED` 或 `CANCELLED` |
| `due_at` | 可选截止时间，毫秒时间戳 |
| `reminder_at` | 可选提醒时间，必须晚于创建或修改时刻 |
| `source` | `MANUAL` 或 `CHAT` |
| `conversation_id` | 可选来源会话，为后续追溯保留 |
| `created_at` / `updated_at` / `completed_at` | 生命周期时间 |

`agenda_plans` 与 `agenda_plan_stages` 是长期计划的权威表：

| 实体 | 核心内容 |
| --- | --- |
| 计划 | 稳定 ID、标题、说明、地点、状态、发生时间、来源、来源引用与生命周期时间 |
| 阶段 | 所属计划、顺序、状态、计划/触发/截止/提醒时间，以及相对计划发生时间的可选偏移 |

阶段随父计划级联删除；完成阶段不会自动完成父计划，父计划状态需要独立落定。数据库 v37→v38 只新增
`agenda_tasks`，v38→v39 只新增长期计划、阶段表与索引，两次迁移都不修改或清理既有用户数据。

## 4. AI 工具契约

普通聊天始终可见以下本地工具：

| 工具 | 行为 | 是否确认 |
| --- | --- | --- |
| `task_list` | 读取当前可见待办 | 否 |
| `task_create` | 创建待办或提醒 | 是 |
| `task_update` | 修改标题、备注、截止或提醒时间 | 是 |
| `task_complete` | 完成或恢复待办 | 是 |
| `task_delete` | 永久删除待办 | 是 |

时间参数接受 ISO-8601 或设备时区下的 `yyyy-MM-dd HH:mm`。写操作必须走普通聊天已有的工具确认机制；
工具和右侧栏共享同一个 Repository，禁止产生第二份任务状态。

长期计划工具遵守同一审批边界：

| 工具 | 行为 | 是否确认 |
| --- | --- | --- |
| `plan_list` / `plan_get` | 读取计划摘要或完整阶段时间线 | 否 |
| `plan_create` | 一次创建父计划及有序阶段 | 是 |
| `plan_update` | 修改父计划；相对阶段时间随发生时间重算 | 是 |
| `plan_stage_update` | 修改单个阶段及其时间 | 是 |
| `plan_stage_complete` | 完成或恢复单个阶段 | 是 |
| `plan_set_status` | 独立设置父计划状态 | 是 |

## 5. 提醒与降级

- 提醒由 WorkManager 使用唯一任务名调度；修改、完成或删除待办时同步替换或取消。
- 长期计划按阶段调度提醒；应用冷启动、设备重启、系统日期时间或时区变化后会从 Room 重建仍有效的提醒。
- Android 13 及以上需要通知权限；拒绝通知权限不会阻塞待办保存。
- 过期提醒不进入调度，恢复已完成待办时会清除已经过期的提醒时间。
- 日历读取失败只清空当前日历投影，不影响本地待办。

## 6. 验收基线

- 冷启动后待办仍存在，数据库升级不破坏既有数据。
- 手动新增的待办立即出现在右侧栏，聊天工具创建的待办进入同一列表。
- 完成、恢复、删除会同步更新列表和提醒调度。
- 不授权日历时待办完整可用；授权后能看到近期系统事件并跳转到系统日历。
- 所有 AI 写操作都会要求用户确认，读取待办不会弹确认。
- 长期计划可以用绝对时间或相对发生时间表达跨周、跨月阶段；当前阶段会进入右侧行动投影。
- 完成阶段不会误完成父计划；计划、阶段与提醒在 v38→v39 迁移及冷启动后仍可读回。
