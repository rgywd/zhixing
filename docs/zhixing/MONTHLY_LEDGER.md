# 月度收支汇总契约

状态：v1 实施契约（2026-07-26）

## 目标与边界

知行允许用户在普通聊天中上传多渠道账单，由当前聊天模型分析后，把结果保存为本地月度汇总。
该能力面向“这个月各渠道花了多少、整月去重后是多少”这类低颗粒度复盘，不建设交易级账本。

持久化范围严格限定为：

- 一个自然月、一个币种的一条整月汇总；
- 该整月汇总下的若干渠道汇总；
- 覆盖度、置信度和口径警告等汇总元数据。

不保存逐笔交易、商户、分类、账户余额、附件 URI、附件正文、OCR 中间结果或模型推理内容。股票、
基金持仓和行情不属于本契约。

## 输入链路

```text
普通聊天上传材料
→ 聊天模型读取图片或已抽取的文档文本
→ 模型识别月份、币种、渠道与渠道汇总
→ 模型判断是否需要跨渠道去重
→ monthly_spending_summary(save)
→ 用户批准本次最终汇总
→ Room 原子替换该月该币种的汇总
```

工具不自行读取附件。材料不完整、月份不确定或跨渠道重复无法判断时，模型应先说明限制或向用户追问，
不得提交看似精确的汇总。

当前输入能力以现有聊天链路为准：

| 材料 | 当前处理 |
| --- | --- |
| 截图、照片、长图 | 支持；主模型有图片能力时直接分析，否则按现有 OCR 配置降级 |
| 文本型 PDF | 支持现有文本抽取 |
| CSV、纯文本 | 支持现有文本读取 |
| 扫描 PDF | 不保证识别；当前没有逐页图片 OCR |
| XLS/XLSX | 不保证识别；当前文档转换器没有电子表格解析器 |

上传到应用私有 `files/upload/` 的图片和文档只作为本次月度汇总的临时输入。模型首次产出
`monthly_spending_summary(save)` 时，应用只用消息 ID 把工具调用绑定到工具链前最后一条用户消息，
且该消息本身必须包含受管图片或文档；不会跨过后续纯文本消息向前猜测旧附件，也不会把文件名、路径、
OCR 文本或正文复制到工具参数和标记。一个批次的多渠道材料应作为同一条用户消息的多个附件发送；
多个币种或连续多次 `save` 会沿用同一来源批次。

只有本轮模型调用新产生了至少一个严格成功的 `save`、当前选中工具链已经没有未执行工具、同一来源
批次关联的所有 `save` 都经用户批准并返回严格成功，而且脱敏后的消息节点已经先写入 Room 后，应用
才会从绑定的来源消息移除附件引用并清理对应 OCR 缓存。失败轮次留下的旧成功输出不会在下一轮无关对话
结束时补触发清理。任何一笔仍在等待、被拒绝、取消或失败，都会保留整批附件以便重试。聊天会在原消息
没有其他内容时保留一条不含文件名和路径的占位文本，已写入的月度汇总不受影响。

物理文件删除前还会按规范化受管路径合并检查全部持久化会话和活跃会话；任一会话读取失败时按仍有引用
处理并保留物理文件。同一文件仍被其他消息、分支、媒体
类型或工具结果引用时，只脱敏本次来源消息，不删除共享文件。文件系统或缓存存储异常可能留下无来源
消息引用的本地残留，但后续整对象保存必须再次应用已提交的脱敏目标，不得把原附件引用写回聊天。

模型失败、用户拒绝或取消审批、工具未执行、返回失败，以及 `query` / `delete` 操作都不会触发清理，
原附件会继续保留以便用户重试。外部 `content://`、网络 URL 和不在应用受管上传目录内的文件也不由该
流程删除。

## 数据口径

金额由工具接收十进制定点字符串，并按 `minorUnit` 精确转换为 `Long` 最小货币单位；禁止使用浮点数。
月份采用 `YYYY-MM`，币种采用三个大写字母的 ISO 4217 代码。不同币种分别展示，未经用户确认不得换算。
月度账本只记录已经开始的自然月，拒绝保存未来月份。

整月汇总的 `aggregationMode` 有两种：

- `RAW_CHANNEL_SUM`：整月收入和支出必须分别等于渠道汇总之和；
- `DEDUPED_ESTIMATE`：整月值是模型跨渠道去重后的估算，允许与渠道之和不同。

支付宝消费同时出现在信用卡账单等场景会造成渠道间重复。因此统计界面必须直接展示已保存的整月值，
不能再次对渠道值求和，也不能用渠道值绘制暗示占比正确的饼图。

覆盖度固定为 `FULL`、`PARTIAL`、`UNKNOWN`。置信度使用 `0..100` 整数。整月与渠道都可以携带简短
警告，用于说明日期覆盖不足、疑似重复或来源不完整。

## AI 工具

向所有普通聊天助手提供一个本地工具 `monthly_spending_summary`，用 `action` 区分：

| action | 行为 | 审批 |
| --- | --- | --- |
| `save` | 原子替换一个月、一个币种的整月与渠道汇总 | 必须 |
| `query` | 查询指定月份，可按币种过滤 | 不需要 |
| `delete` | 删除指定月份的一个币种或全部币种 | 必须 |

缺失或未知 action 默认要求审批，并在执行时返回稳定的结构化错误。`save` 是整月快照写入，不做增量
叠加；同一参数重复提交得到相同业务状态，旧渠道不会残留。`delete` 是幂等操作。

工具 schema 禁止额外字段，执行时也会拒绝 action 或渠道对象中的未知字段。模型返回的工具调用在进入
聊天状态和持久化之前，还会按 action 剥离顶层与渠道对象中的未知字段；无法解析或净化失败时按空对象
处理，不保留原始输入。工具参数和返回值只能出现最终汇总，不得包含附件路径、原始正文或逐笔明细。
聊天审批卡就是本次写入的最终确认，不再增加第二套入账页面。

## 统计界面

复用现有 `Screen.Stats`，在同一页面提供“对话”和“收支”两个子 Tab，不新增路由：

- “对话”保持现有热力图、会话与 Token 统计；
- “收支”按月切换，并按币种展示整月收入、支出、净额、聚合口径和覆盖状态；
- 渠道区域标明“可能含跨渠道重复”，只展示各渠道汇总；
- 没有数据时，引导用户回到聊天上传账单。

界面是只读统计视图，不提供逐笔编辑或上传入口。

## 本地事实与迁移

Room 是唯一事实来源。整月父记录与渠道子记录在同一个事务内替换，删除父记录必须级联删除渠道记录；
观察接口以一个原子关系结果提供整月与渠道，避免界面看到短暂不一致。

成功导入后的聊天附件和 OCR 缓存不是账本事实来源，也不属于长期保留数据。清理顺序固定为“同批工具
全部成功 → 来源消息脱敏落库 → 全局引用检查 → 删除无其他引用的受管附件 → 删除本批 OCR 缓存”；
会话落库失败或无法读回确认脱敏结果时不得删除原文件。

本能力从数据库 v40 升级到 v41，只新增汇总表和索引。迁移不得修改、删除或重建既有会话、事项、
长期计划、Work 会话或用户文件。
